# neosloc

`sloccount` counted lines of code and fed them to COCOMO to estimate the effort to *build*
software. With LLMs writing code, lines are cheap and that estimate has lost its meaning.
What is still expensive is everything *around* the code: how easily other systems and
agents can call it, run it, rely on it and change it safely.

neosloc measures that: **integrability**. Point it at a repository and you get a level
(0–4) per dimension, the evidence behind each level, the gaps phrased as actions, and an
estimate of the effort to bring the system up to "solid", which takes the place of COCOMO.

```
$ python3 -m neosloc /srv/aiproxy
Interface surface   ■■■□  3 solid      The framework generates a contract from code, so it tracks the implementation.
                      + routes:fastapi/flask: 15 route declarations in 3 files (app/routes/admin.py)
                      + generated-spec: FastAPI (auto OpenAPI) (app/main.py)
                      - Check the generated spec into the repo so changes are reviewable and diffable.
...
Integrability index (0-4, assessed dimensions):  2.50
Retrofit effort to level 3 (agent-assisted):     0.8 person-days
Wrappability:                                     cheap to wrap
```

No dependencies, Python ≥ 3.8. `python3 -m neosloc PATH... [--json] [-v] [--only KEYS]`,
or `pip install .` for a `neosloc` command.

## Dimensions

| Key | Dimension | Status | What it asks |
|---|---|---|---|
| `interface` | Interface surface | **v0.1** | Is there a machine-readable contract (OpenAPI, GraphQL, proto, AsyncAPI, generated by a framework), how much of the detected routes does it cover, and are there extra surfaces (MCP server, CLI `--json`, SDK)? |
| `stability` | Contract stability | **v0.1** | Semver tags, changelog, API versioning, deprecation markers, and the **actual git history of OpenAPI files**: operations removed between revisions without deprecation. |
| `events` | Events | planned | Webhooks, event streams, CDC, AsyncAPI. |
| `identity` | Identity | planned | OAuth2/OIDC, scoped tokens, service accounts, SCIM. |
| `portability` | Data portability | planned | Bulk export/import, open formats, documented schema. |
| `ergonomics` | Agent ergonomics | planned | RFC 9457 errors, idempotency keys, dry-run, pagination, rate-limit headers, `llms.txt`. |
| `embeddability` | Embeddability | **v0.1** | Container image, compose/Helm/IaC, environment-driven and documented config, headless entry point, library packaging. |
| `extensibility` | Extensibility | planned | Plugins, hooks, scripting. |
| `observability` | Observability | planned | OpenTelemetry, health/readiness, structured logs. |
| `legibility` | Change legibility | **v0.1** | The heir to SLOC: size in **tokens per module** (does a unit of change fit in context?), file-level import cycles, test/source ratio, typed share, CI, lockfiles, agent docs (`AGENTS.md`, `CLAUDE.md`, `llms.txt`). |

Levels: 0 absent · 1 ad hoc · 2 partial · 3 solid · 4 exemplary. There is deliberately no
single overall score shown as a headline; the mean ("integrability index") is reported
alongside the per-dimension levels so it can't hide them.

## The estimate

```
effort = Σ base[d] × (3 − level[d]) × legibility_multiplier × size_factor
```

`base[d]` is agent-assisted person-days per level per dimension at ~250k tokens;
`size_factor` is √(tokens / 250k), clamped to 0.5–4; the legibility multiplier
(0.5–2.5) captures that hard-to-change code makes every other fix more expensive. All
coefficients are in `neosloc/estimate.py` and are **uncalibrated guesses**. Calibrating them
against real retrofits is the main open work item.

The result is reported twice: as person-days, and as *wrappability* (cheap to wrap →
replace or wrap externally). A legacy system with no API but a clean CLI, tests and a
readable schema is often cheap to wrap, and that is what re-evaluating old applications
should surface.

## Roadmap

1. **Static mode** (this release): repository only.
2. **Runtime mode**: probe a running instance for error formats, auth flows, pagination,
   rate-limit headers, health endpoints, and whether the served spec matches behaviour.
3. **Agentic mode**: give an LLM only the docs/spec and a fixed set of integration tasks
   (create, query, subscribe, export). Measure success rate, tokens and retries. This
   measures integrability directly instead of through proxies.
4. The planned dimensions above, then calibration of the estimate.

## Known limits

- Route counting is regex-based per framework idiom: good for orders of magnitude, not exact.
- YAML OpenAPI is parsed by indentation (no YAML dependency); `$ref`'d path files are not followed.
- The import graph covers Python and JS/TS only.
- Tokens are estimated at 4 characters per token.
- Content signals are regexes over source text, so string literals can match (neosloc
  scanning itself sees its own patterns as env reads and deprecation markers).
